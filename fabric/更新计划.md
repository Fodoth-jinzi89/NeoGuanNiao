# Fabric 更新计划

审查日期：2026-09-07。目标：Minecraft 1.21.1 Fabric，以当前工作区 NeoForge 版的功能为对齐基线。

本次只进行源码审查并编写计划，没有修改实现或构建配置，没有启动 Fabric 客户端/服务端。下列“已确认”指源码缺口已确认，不代表已复现对应的运行时故障。审查包含工作区尚未提交的修改。

## 总体结论

Fabric 目前有基础注册和部分渲染适配，但尚未形成完整可玩的功能闭环。大量玩法、界面、网络处理器已经在 common 中，主要工作是补齐 Fabric 注册、事件、网络和渲染入口，而不是重新实现整套玩法。

优先顺序：**基础注册与启动 → 物品显示和图鉴 → 网络与相机 → 战斗/进度/村民 → 自动化与兼容 → 完整回归**。基础注册未补齐前，不宜把“能编译”当作“能正常游玩”。

下文源码路径均相对于仓库根目录；为减少重复，Java 路径用以下前缀：

- `F/` = `fabric/src/main/java/net/fodoth/skina/neoguanniao/`
- `N/` = `neoforge/src/main/java/net/fodoth/skina/neoguanniao/`
- `C/` = `common/src/main/java/net/fodoth/skina/neoguanniao/`

## P0：先补齐运行基础

### 1. 基础注册缺失【已确认】

- [x] 在 Fabric 初始化时注册 `NeoGuanNiaoBirdData.BIRD_DATA`。
- [x] 注册 `NeoGuanNiaoDataComponents.DATA_COMPONENTS`，覆盖鸟蛋、羽毛、图鉴布局和羽扇模式等数据。
- [x] 在鸟类数据就绪后填充 `NeoGuanNiaoBirdSkins`、`NeoGuanNiaoBirdModels` 索引。
- [x] 注册 `NeoGuanNiaoCriteriaTriggers` 中的四个自定义进度条件。
- [x] 核对注册依赖顺序，避免在 RegistrySupplier 可用前调用 `.get()`。

证据：`F/NeoGuanNiaoFabric.java` 的初始化仅注册方块、物品、声音、配方、实体、方块实体、粒子、创造标签和生成表。对照 `N/NeoGuanNiaoNeoForge.java`、`N/event/NeoGuanNiaoModEvents.java#registerBirdSkins`。`C/registry/NeoGuanNiaoDataComponents.java`、`NeoGuanNiaoBirdData.java` 中声明注册项不等于已经调用注册入口。

影响：鸟类数据读取、物品持久化/同步及进度加载存在运行失败风险；具体首次失败位置需要启动验证。

验收：客户端进入新世界、专用服务端启动成功；12 种鸟可生成；鸟蛋/羽毛/羽扇数据保存后重进不丢失；进度资源无未知条件报错。

### 2. 鸟类默认属性与生成条件【已确认】

- [x] 为 12 种鸟注册对应 `createAttributes()` 的默认属性。
- [x] 为 12 种鸟接入 `ON_GROUND`、`MOTION_BLOCKING_NO_LEAVES` 和各自 `canSpawn` 判定。
- [x] 核对 Fabric 生物群系生成表与 NeoForge 12 个 biome modifier 的栖息地、权重、群体数量。

证据：`F/NeoGuanNiaoFabricSpawns.java` 只调用 `BiomeModifications.addSpawn`；Fabric 和 common 中未发现默认属性及 SpawnPlacements 注册入口。对应实现位于 `N/event/NeoGuanNiaoModEvents.java#onEntityAttributeCreation`、`#onRegisterSpawnPlacements`。

说明：Fabric 已有 12 种鸟的生物群系生成表，不能把自然生成整体记为“完全未移植”；缺的是属性和落点判定等必要接入。

验收：逐种召唤无属性异常；不同地形/时段的自然生成符合共享 `canSpawn` 规则。

### 3. 服务端配置平台实现缺失【已确认】

- [x] 增加 `F/platform/fabric/ConfigHooksImpl.java`，实现 `cameraLimits()`。
- [ ] 服务端上传权限、容量、速率、超时等限制必须从配置读取。

证据：`C/platform/ConfigHooks.java` 使用 `@ExpectPlatform`，当前只有 NeoForge 同名实现。`F/platform/fabric/ClientHooksImpl.java` 中另一个 `cameraLimits()` 方法不对应这个平台类，不能替代它。

验收：生产 Fabric JAR 中所有平台转发目标均存在；实际调用服务端相机限制不报缺类/缺方法错误。

## 已有内容：优先复用

- common 已含鸟类实体、AI、繁殖孵化、饲料、鸟笼/浴盆/鸟巢、羽扇、相机数据、照片管理、图鉴界面、配方与资源。
- Fabric 已有基础内容注册、12 种鸟的生物群系生成表和实体渲染、鸟笼/浴盆/鸟巢方块实体渲染、七种粒子注册、三个布局键注册。
- common 的共享 mixin 已由 Fabric 元数据声明；仍需最终产物运行验证。

“代码在 common 中”仅意味着可以复用，必须同时确认所需注册、平台实现、事件和资源都已接通。

## 实施批次与完成条件

1. **可启动基线**：完成 P0，运行 Fabric 客户端和专用服务端；生成所有鸟类并测试物品数据存取。
2. **基础交互可用**：完成物品渲染、图鉴、配置；检查背包/手持/世界放置外观。
3. **拍照完整闭环**：网络、生命周期、相机事件、照片渲染及命令一起验收，使用两个客户端验证。
4. **玩法对齐**：羽扇、进度、村民、鸟巢自动化逐项对比 NeoForge。
5. **发布回归**：JDK 21 下执行 `./gradlew build`；分别运行 `:fabric:runClient` 和 `:fabric:runServer`；用最终 Fabric JAR 在正常加载器环境复核。根据运行配置实际目录检查日志与崩溃报告。

每批次只改对应功能所需文件，优先复用 common 与现有依赖。除非确有需要且另行获得授权，不改 `build.gradle`/`settings.gradle`。本计划不要求跨加载器共用世界；若后续提出此需求，再单独处理存档兼容。

发布完成条件：上述必要项全部验收；可选兼容项有明确支持/暂不支持结论；有/无兼容模组两种组合均测试；NeoForge 构建和相关既有功能不回退。
